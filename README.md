# ETSI 3GPP & GSM Explorer

Самостоятельная реализация в чистой orphan-ветке `etsi-3gpp-explorer`.
В ветке только файлы этого explorer; MCP-сервер не является зависимостью.

- `frontend/index.html` + `styles.css`: серверный HTML-шаблон, браузерные стили,
  стандартные ссылки и GET-форма, без JavaScript. Облик обычного индекса документов.
- `backend/app.py`: FastAPI, HTML-каталог и REST API, SQLite только для чтения.
- `indexer/`: Go, обход ETSI deliver, Firefox 135 User-Agent и Firefox 135
  ClientHello через `tls-client` / `bogdanfinn/utls`, Poppler PDF → текст,
  транзакционное построение SQLite FTS5 и частотного индекса.

## Запуск на сервере

Нужны Go 1.26.1+, Python 3.11+, `pdftotext` (`apt install poppler-utils`).
Запускать команды из корня проекта. Docker не требуется.

```sh
make setup
make build
# Проверка на одной современной и одной GSM-спецификации:
./bin/etsi-indexer --source https://www.etsi.org/deliver/etsi_ts/123500_123599/123501/
./bin/etsi-indexer --source https://www.etsi.org/deliver/etsi_ts/100900_100999/100940/
make serve
```

Открыть `http://127.0.0.1:8000/index.html`. Это серверная страница: открытие
Jinja-шаблона напрямую с диска не выполняет поиск. Поле поиска обновляет выдачу
после Enter / Search. Обновление на каждый символ несовместимо с требованием
«без JS»; скрытых скриптов, HTMX и внешних JS-библиотек нет.

Полный обход (длительная операция, выполняется на хосте):

```sh
./bin/etsi-indexer --workers 4 --db data/explorer.db
# Тот же список идентификаторов, что в локальной базе MCP:
./bin/etsi-indexer --mcp-db /absolute/path/to/3gpp.db --db data/mcp-explorer.db
EXPLORER_DB=data/mcp-explorer.db .venv/bin/python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Для ограничения каталогом MCP используйте отдельный, изначально пустой выходной
файл: индексатор не удаляет ранее индексированные документы вне нового фильтра.
MCP-база открывается read-only; таблица `specs.id` задаёт набор спецификаций.
Версии берутся из ETSI, наиболее новые опубликованные, и могут отличаться от MCP.
Отсутствующие идентификаторы записываются в `<db>.missing.txt`; неполный каталог
даёт ненулевой код завершения. Отсутствующий в ETSI документ не подменяется DOCX.

Автообход охватывает TS, TR, EN, ETR, I-ETS и исторический GSM GTS. Не относящиеся
к 3GPP/GSM PDF пропускаются по идентификатору на обложке. Для каждого каталога
выбирается новейшая опубликованная версия с PDF, в базе остаётся одна версия
на идентификатор. Серии 01–20 и документы с GSM на обложке выделены в GSM;
современные серии 21+ остаются в 3GPP, включая современные GERAN/GSM-спеки.
Имена 3GPP и ETSI различаются: например, 23.501 опубликован как ETSI TS 123 501.
Нельзя строить полный GSM-каталог простым добавлением `1` к номеру спецификации.

Повторный запуск обновляет базу; SHA-256 пропускает повторную конвертацию PDF
по тому же URL. Обновление документа атомарно, неудачная конвертация сохраняет
старую версию. WAL позволяет параллельное чтение веб-сервером. `--workers` 1–16;
каждый запрос имеет timeout 120 s, лимит PDF 100 MiB, до трёх попыток на
сетевую ошибку / HTTP 429 / 5xx. `HTTPS_PROXY` поддерживается, проверка TLS
включена. На прокси с TLS-терминацией внешний fingerprint определяет прокси.
PDF обрабатывается внешним `pdftotext`, постоянная копия PDF не хранится.

## Алгоритм поиска

1. Одинаковая нормализация в Go и Python: Unicode NFKD, удаление комбинируемых
   диакритик, нижний регистр, сохранение букв и десятичных цифр. Спецзнаки
   превращаются в границы слов. `PDU-session`, `PDU/session`, `PDU session`
   эквивалентны; `PDUsession` — другое слово. Разметка FTS пользователя не исполняется.
2. FTS5 ищет пересечение posting lists всех слов в пределах одного раздела.
   Это поиск полных слов, без fuzzy, substring и stemming. Пустой запрос или
   только пунктуация открывает каталог. Лимит: 256 символов / 16 разных слов.
3. Частоты каждого слова в заголовке и тексте вычисляются **один раз при
   индексации**, в `term_counts` с составным ключом `(term, section_id)`.
   Поиск не сканирует тела документов для подсчёта. Для нескольких слов
   частота равна сумме их отдельных употреблений; это AND, а не поиск фразы.
4. Порядок разделов: есть слово запроса в заголовке → больше употреблений
   в собственном тексте раздела → больше употреблений в заголовке → порядок
   раздела в документе. Текст дочерних разделов не дублируется в родителях.
   Документы упорядочиваются по лучшему найденному разделу, затем по номеру.
5. На странице 25 документов; для каждого 1–50 превью (по умолчанию 3).
   «More matching sections» открывает следующие разделы конкретного документа:
   таким образом доступны **все** совпавшие разделы, включая выходящие за лимит
   превью. Превью — до 360 исходных символов вокруг первого найденного слова.
   Оригинальная пунктуация сохраняется; HTML автоматически экранируется Jinja.

FTS и частотный индекс читаются по словам запроса, не по объёму корпуса.
Частые слова всё равно имеют длинные posting lists; максимальная скорость на
полном корпусе зависит от его размера, SSD и селективности запроса.
SQL CTE с частотами материализуется, чтобы SQLite не пересчитывал агрегацию
для каждого совпадения. Полные тексты извлекаются только для показанных превью.

## Разделы и страницы

Оглавление извлекается из PDF; заголовки проверяются на указанной печатной
странице. Если оглавление устарело, допускается проверенное смещение ±2 страницы.
Отсутствующий заголовок, непоследовательное оглавление или PDF без текстового
слоя дают ошибку с адресом источника и ненулевой exit code; OCR не выполняется.
Многострочные заголовки поддерживаются по первой строке тела. Разделы без
номера в оглавлении (например, предисловие) не входят в индекс.

В `sections.page` хранится **печатная** страница. Ссылка всегда
`https://www.etsi.org/deliver/...pdf#page=<printed+1>`, т.е. печатная страница
42 открывает физическую страницу PDF 43. Поправка применяется только в API/
шаблоне, никогда повторно в парсере. Неверные страницы не угадываются.

## REST

- `GET /api/search?q=pdu-session&family=3gpp&series=23&previews=3&page=1`
- `GET /api/search?q=pdu&spec=23.501&previews=3&section_page=2`
- `GET /api/search` — каталог и оглавления, `family=gsm` — только GSM.
- `GET /`, `/index.html` — те же запросы в HTML.
- `GET /styles.css`, `GET /health` (503, пока нет индекса).
- `GET /docs` — Swagger UI FastAPI (документация API; основной frontend без JS).

Ответ содержит документы, число совпавших разделов, выбранные превью с
номерами и ссылками, счётчики частот, `next_sections_url`, каталог серий и
пагинацию. Ошибки параметров: 422, недоступная база/схема: 503.
Веб-процесс не создаёт пустую базу и не запускает индексатор из HTTP-запроса.

В production можно поставить nginx перед `127.0.0.1:8000`; индексатор запускать
таймером на том же хосте с доступом записи к data/, FastAPI — с чтением data/
и SQLite WAL/SHM. Не заменять файл базы посреди работы; индексатор обновляет
документы транзакционно. Требуется SQLite 3.35+ с FTS5, как в Python 3.11+.

## Проверки

```sh
make test
# Дополнительно интеграционная проверка настоящего PDF:
pdftotext -layout path/to/spec.pdf /tmp/spec.txt
ETSI_TEST_TEXT=/tmp/spec.txt go test ./indexer -run TestRealPDF -v
```

Проверены нормализация, приоритет заголовка, частота в тексте, ограничения,
фильтры, доступ ко всем страницам превью, экранирование, page+1, read-only,
триггеры FTS, частотный индекс и rollback обновления. Обе копии schema.sql
должны совпадать (проверяется тестом; одна нужна для Go embed).
Полный каталог ETSI при разработке не скачивался; реальные интеграционные
прогоны выполнены для TS 23.501 V19.9.0 и GSM 04.08 V7.21.0.

## Готовый Linux amd64 бинарник

`dist/etsi-indexer-linux-amd64` — статический ELF x86-64, CGO отключён,
GOAMD64=v1; Go и libc на целевом сервере не нужны. Проверка:

```sh
cd dist
sha256sum -c SHA256SUMS
chmod +x etsi-indexer-linux-amd64
cd ..
sudo apt-get install poppler-utils
./dist/etsi-indexer-linux-amd64 --db data/explorer.db --workers 4
```

Для пересборки: `make build-amd64`. Контрольные суммы лежат в `dist/SHA256SUMS`.

## Docker backend на 127.0.0.1:10808

Docker-образ содержит FastAPI и frontend; индексатор запускается отдельно
на хосте. База сохраняется в `./data/explorer.db`, не внутри образа. После
заполнения базы:

```sh
EXPLORER_UID=$(id -u) EXPLORER_GID=$(id -g) docker compose up -d --build
curl http://127.0.0.1:10808/health
# Страница: http://127.0.0.1:10808/index.html
# API: http://127.0.0.1:10808/api/search?q=pdu-session
```

Compose собирает Linux amd64-образ `etsi-explorer-backend:local`. Только
локальный интерфейс хоста публикует порт: `127.0.0.1:10808:8000`.
В контейнере Uvicorn слушает `0.0.0.0:8000`, два worker-процесса.
Без базы контейнер отвечает 503 и healthcheck показывает unhealthy до её
создания; не генерирует пустую БД. Индексация может продолжаться на хосте
параллельно с поиском; база работает в режиме WAL.

Каталог data/ монтируется с записью для служебных SQLite `-wal`/`-shm` файлов:
подключения FastAPI остаются строго `mode=ro` + `query_only`, изменение данных
через backend невозможно. Это обеспечивает чтение активной WAL-базы без
небезопасного `immutable=1`. UID/GID контейнера должны совпадать с владельцем
файлов индексатора (по умолчанию 1000:1000, настраиваются переменными выше).
Корневая ФС контейнера read-only. При использовании `--db` с другим именем
измените `EXPLORER_DB` в compose.yaml.

Остановка: `docker compose down` — данные в ./data сохраняются.

В окружении с корпоративным CA передайте его только на этапе сборки:

```sh
docker build --secret id=proxy_ca,src=/path/to/ca-bundle.pem -t etsi-explorer-backend:local .
docker compose up -d --no-build
```

Готовый экспортированный образ также можно загрузить без сборки:

```sh
docker load -i etsi-explorer-backend-linux-amd64.tar.gz
EXPLORER_UID=$(id -u) EXPLORER_GID=$(id -g) docker compose up -d --no-build
```

Проверка образа выполнена на Linux amd64: HTTP 200 для `/health`,
`/index.html`, поиска по двум спецификациям и чтения свежей WAL-базы.
