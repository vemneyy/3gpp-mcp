# ETSI 3GPP & GSM Explorer — v2

Самостоятельная чистая ветка `etsi-3gpp-explorer`. Frontend: index.html + CSS
без JavaScript; backend: FastAPI; индексатор: Go, Firefox 135 User-Agent и
ClientHello через tls-client / uTLS, pdftotext из Poppler.

Обновление существующей установки: **[UPDATING.md](UPDATING.md)**. Перед новым
backend требуется миграция старой базы: `--db data/explorer.db --migrate`.
Миграция автоматически делает резервную копию и работает без скачивания PDF.

## Установка

Нужны Docker + Compose, `poppler-utils` для индексатора. Go/Python на хосте
не нужны при использовании готового `dist/etsi-indexer-linux-amd64` и Docker.
Бинарник — статический Linux x86-64 / GOAMD64=v1, CGO отключён.

```sh
chmod +x dist/etsi-indexer-linux-amd64
(cd dist && sha256sum -c SHA256SUMS)
# Сначала одна спецификация для проверки:
./dist/etsi-indexer-linux-amd64 --db data/explorer.db --source https://www.etsi.org/deliver/etsi_ts/123500_123599/123501/
EXPLORER_UID=$(id -u) EXPLORER_GID=$(id -g) docker compose up -d --build
curl http://127.0.0.1:10808/health
```

Сайт: http://127.0.0.1:10808/index.html. У backend внутри контейнера порт 8000,
на хосте публикуется только 127.0.0.1:10808. База в ./data, UID/GID контейнера
должны совпадать с владельцем базы. FastAPI открывает SQLite `mode=ro` и
`query_only`; запись в data нужна только для WAL/SHM. Корневая ФС контейнера
read-only. Два Uvicorn worker. Nginx может проксировать на этот адрес.
Без базы или со старой схемой health возвращает 503.

Полный каталог (длительная операция на хосте):

```sh
./dist/etsi-indexer-linux-amd64 --db data/explorer.db --workers 4
# Ограничение списком спецификаций MCP, на изначально пустом выходном файле:
./dist/etsi-indexer-linux-amd64 --mcp-db /absolute/path/3gpp.db --db data/mcp-explorer.db
```

--mcp-db читает specs.id, версии выбираются из ETSI; отсутствующие документы
перечисляются в <db>.missing.txt, код завершения ненулевой. Автообход: ETSI TS,
TR, EN, ETR, I-ETS, GTS. Не относящиеся к 3GPP/GSM PDF пропускаются. На один
идентификатор хранится новейшая доступная версия. Семейство GSM определяется
обложкой или сериями 01–20; современные серии 21+ остаются в 3GPP.

Повторная индексация сравнивает SHA-256. PDF скачивается во временный каталог,
конвертируется и удаляется. Документ обновляется атомарно; неудачная конвертация
сохраняет прежнюю версию. --workers 1–16, timeout 120 s, до трёх сетевых попыток,
PDF до 100 MiB. HTTPS_PROXY поддерживается; TLS verification включена. На
TLS-терминирующем прокси внешний fingerprint определяет прокси.

## Хранение и поиск v2

Один SQLite-файл, отдельные таблицы:

| Таблица | Содержимое |
| --- | --- |
| documents | Номер, название, семейство, серия, версия, URL, SHA-256 документа |
| sections | Номер и название раздела, печатная страница, связь с документом |
| section_text | Исходный текст раздела; читается только для нужных превью |
| postings | Слово → раздел/документ и частоты в заголовке/тексте |
| term_stats | Число разделов с каждым словом для выбора самого редкого |

Тексты и их нормализованные копии не дублируются в поисковой таблице. Старый
FTS5 и повторное ранжирование SQL CTE убраны. postings — covering B-tree с
ключом (term,section_id); фраза из нескольких слов ищется пересечением списков
от самого редкого слова. Остальные слова проверяются точечными индексными
запросами. Весь набор кандидатов читается один раз, числа упоминаний не
вычисляются из текста. Для каждого документа сохраняется ограниченный top-K;
только после выбора страниц/превью читаются конкретные тексты по primary key.
Кеш выдачи не используется, каждое обращение видит согласованный WAL snapshot.
Точные количества совпадений требуют пройти все совпавшие postings: частые
слова всё ещё дороже редких; полная сортировка текстов не выполняется.

Нормализация одинаковая в Go/Python: NFKD, удаление комбинируемых диакритик,
нижний регистр, сохранение букв/десятичных цифр, спецзнаки — границы слов.
PDU-session = PDU/session = PDU session. Полные слова, AND в одном разделе;
без fuzzy/stemming/substring. Для нескольких слов частота — сумма их отдельных
употреблений. 256 символов, до 16 разных слов; синтаксис SQL/FTS не исполняется.

Ранг: упоминание в заголовке, затем число упоминаний в собственном тексте,
затем частота в заголовке, затем порядок раздела. Документы сортируются по
лучшему разделу и номеру спецификации. 25 документов на странице, 1–50 превью.
Следующие совпавшие разделы доступны по ссылке. Превью до 360 исходных символов,
HTML экранируется. Главная показывает только названия документов. Оглавление
открывается отдельно и выдаётся по 100 разделов без загрузки их текстов.
Выбор серии/коллекции и технические пояснения удалены из интерфейса; API-фильтры
сохранены для совместимости.

## Разделы и ссылки

Оглавление PDF проверяется по реальным заголовкам; допускается исправление
устаревшей страницы в пределах ±2. Многострочные заголовки сопоставляются по
первой строке. PDF без текстового слоя/оглавления, отсутствующий заголовок или
непоследовательные разделы дают ошибку; OCR отсутствует. Ненумерованные
предисловия в индекс не входят. В БД печатная страница; PDF URL всегда
#page=<печатная+1>, поправка применяется один раз при формировании ответа.

## API и разработка

- GET / и /index.html — каталог / HTML-поиск.
- GET /document/23.501?page=2 — отдельное оглавление, 100 разделов на страницу.
- GET /api/search?q=pdu-session&previews=3&page=1
- GET /api/search?q=pdu&spec=23.501&previews=3&section_page=2
- GET /api/search — только метаданные документов, sections пусты.
- GET /health — status=ok, schema=2; /docs — документация FastAPI.
- API-фильтры family=3gpp/gsm и series=23 остаются доступными.

Для сборки нужны Go 1.26.1+, Python 3.11+. `make setup`, `make test`,
`make build-amd64`, `make serve` (без Docker: localhost:8000).
Schema SQL дублируется для Go embed и проверяется тестом.

Docker build в окружении с корпоративным CA:

```sh
docker build --secret id=proxy_ca,src=/path/to/ca-bundle.pem -t etsi-explorer-backend:local .
docker compose up -d --no-build
```

Проверены миграция/rollback/idempotence, частотные счётчики и cascade-delete,
разделение загрузки заголовков/текстов, приоритет заголовка, пересечение от
редкого слова, доступ к следующим превью/оглавлению, page+1, XSS-экранирование,
валидация, read-only. Интеграция на TS 23.501 V19.9.0 и GSM 04.08 V7.21.0;
полный каталог при разработке не скачивался.
